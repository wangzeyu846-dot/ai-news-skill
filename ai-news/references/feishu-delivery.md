# 飞书交付与验证

## 接入选择

先检查真实可调用的飞书/Lark 连接、MCP 或已配置 API，读取其工具说明并使用支持的创建、写入能力。不要编造工具名或认证参数，也不要从本地文件、浏览器存储或界面中提取令牌。

无专用连接时，通过真实可用的浏览器或原生应用控制工具，在用户已登录的飞书会话操作。环境提供 tabbit skill 且 CLI 可运行时遵循该 skill；启动失败可使用可用的原生电脑控制工具，操作浏览器或飞书客户端。不同浏览器、内嵌浏览器不一定共享登录态。

不预设外部连接已经安装，不强制用户创建开发者应用。登录、验证码、权限缺失或空间不明确时，先完成并保存正文，再说明需要用户完成的具体动作。无法交付不影响可独立完成的采集。

## 创建与验证

“给我AI资讯”的目标包含新建飞书文档；在已明确账号和默认空间正常创建、编辑和保存，不对普通保存重复询问。有多个无法辨认的账号或工作空间时，只询问影响交付的缺失信息。

1. 在可写工作目录保存完整 Markdown 草稿，文件名包含实际生成日期与时间，避免覆盖。
2. 通过观察到的创建入口或文档工具新建，记录文档地址。不覆盖现有文档，不写进用户当前打开的其他文件。
3. 设置标题、写入全文，优先原生块或支持的富文本导入。粘贴 Markdown 不代表转换为格式；出现原始标记时用实际编辑器能力修正。
4. 核验开头、中段、结尾、章节及消息条数，确认没有重复、截断、占位文字。检查布局、链接，必要时滚动查看。
5. 等待真实保存信号，并刷新或重新打开后确认标题和正文仍存在。取得真实文档链接后再报告成功。

### 原生应用的富文本路径

在支持 HTML 粘贴的原生控制工具中，可将已核验的正文转换为明确的 HTML 字符串后直接粘贴：主题用 h2、消息用 h3、标签用 strong、细节用 ul/li、来源用 a；分区用 hr。先在独立标题输入区设置标题，再在该新文档的正文输入区粘贴。普通中文文本也优先使用明确文本粘贴，并核对结果，避免输入法导致漏字。

不要把“已执行复制快捷键”当成获得正确剪贴板内容的证明。跨应用复制后如出现旧内容，先撤销本次错误插入，检查恢复状态，再用明确正文的 HTML 粘贴；避免将不可确认的剪贴板内容写入。

粘贴后检查目录中的三类主题和资讯标题、正文开头/中段/结尾，以及真实来源链接。原生编辑器可能按视口虚拟化正文，需通过目录和滚动检查，不能把视口里只显示尾部误判为前文丢失。

不自行改变分享权限、公开文档或发送飞书消息；这些操作需要用户另行指定。

## 失败与恢复

- 创建或写入超时后先检查实际状态，不能直接再创建。找到已创建文档就在原文档恢复；无法确定是否创建时停止重复创建并报告不确定状态。
- 一次写入失败后检查原因，可做一次有依据的修正重试；相同障碍再次发生时停止该路径，不无限重试。
- 创建成功但内容或排版未验证时准确报告状态，提供已有文档地址和完整草稿，说明剩余工作。
- 工具或登录不可用时报告“本地草稿已完成，飞书交付未完成”。接入恢复后复用草稿；用户要求更新或稿件已过时时再刷新资讯。
- 本地草稿用于恢复，不替代目标交付；此次故障不固化为未来永远不可用的规则。
